# 내야 수비 시뮬레이터

VR 야구를 하는 버추얼 스트리머가 내야 수비 판단을 연습할 수 있게 만드는 웹 게임입니다.
투수, 1루수, 2루수, 유격수, 3루수 중 하나를 골라 1인칭 시점으로 플레이합니다. 해설을 직접 쓴 기본 상황 36개(포지션별 7~8개)는 목록에서 고를 수 있고, 랜덤 연습에는 상황 생성기가 만든 621개(포지션별 땅볼 117개, 투수·1루수·3루수는 번트 12개씩 추가)가 함께 나옵니다.

- **송구 판단**: 공을 잡은 뒤 어디로 던질지 고르는 상황. 공과 주자의 도착 시간을 계산해서 판정합니다.
- **위치 판단**: 공이 나에게 오지 않을 때 베이스 커버, 백업, 중계, 커트 위치 중 어디로 갈지 고르는 상황.

투수를 고르면 마운드에서 직접 공을 던진 뒤 바로 수비수가 됩니다 (투수 앞 땅볼과 번트 처리, 1루 커버, 안타 때 홈·3루 뒤 백업).

모든 상황은 오른손 타자 기준입니다.

결과 화면에서 위에서 내려다보는 리플레이를 볼 수 있고, 상황별 기록은 브라우저에 저장됩니다.

## 주루 판단 시뮬레이터 (`runner.html`)

내야 수비와 따로 쓰는 페이지입니다. 구장·선수·화면 부품과 판정 엔진 일부를 같이 쓰고, 첫 화면 목록은 종류별 탭(한 베이스 더 / 플라이 / 땅볼)으로 나뉩니다. 내가 주자가 되어 1인칭으로 뛰면서 판단하고, 지금은 판단 모드만 있어요.

- **한 베이스 더**: 외야 안타 때 1루 주자는 3루까지, 2루 주자는 홈까지, 타자는 2루까지 갈지 정합니다. 베이스 0.6초 전(`RUNNER.commit`)까지 정해야 속도를 줄이지 않고 돌 수 있어서, 공이 잡히는 걸 끝까지 보고 정하면 그만큼 베이스에서 머뭇거립니다.
- **플라이**: 판단이 두 번입니다. 공이 뜨는 순간(1단계) 스타트 / 하프웨이 / 베이스로(태그업 준비) 중 고르고, 베이스를 밟고 있다가 공이 잡히면(2단계) 태그업으로 뛸지 정합니다. 잡히면 베이스에서 떨어져 있던 주자는 귀루해야 하고(늦으면 더블아웃), 떨어지면 1루 주자는 포스라 2루까지 가야 합니다. 타구마다 잡힐 확률이 있어서(빗맞은 타구, 외야 사이 깊은 타구) 잡혔을 때와 떨어졌을 때를 함께 따집니다. 2단계 선택지는 공이 잡히는 순간에만 뜹니다.
- **땅볼**: 타구 방향이 보이는 순간 진루 / 귀루를 고릅니다. 포스(의무 진루)면 무조건 진루가 답이고, 포스가 아니면 수비가 어디로 던지는지에 따라 정합니다. 수비 플레이는 내야 수비 판정 엔진(`scenario.ts`)으로 계산하고, 내 행동을 본 수비가 가장 좋은 곳으로 던진다고 봅니다.

키는 `A`(뒤로: 멈춘다·베이스로·귀루), `S`(하프웨이), `D`(앞으로: 간다·스타트·진루)이고(화살표 ← ↓ →도 같음), 바라보는 곳을 클릭해도 됩니다. 시점은 마우스를 움직이기 전까지 공을 따라갑니다.

판정은 수비와 다르게 기대 득점으로 합니다.

1. 외야수가 공을 잡고(앞으로 오면서 / 제자리 / 뒤로 물러나며) 던지는 시간과 송구 속도(외야수 모두 같음, `RUNNER.throwSpeed`)로 송구가 베이스에 오는 시간을 계산하고, 주자 도착 시간과 비교합니다.
2. 송구에는 오차가 있어서(가끔 빗나감) 시간 차이를 **세이프 확률**로 바꿉니다.
3. 아웃 카운트·주자 상황별 **기대 득점**(MLB 평균, `RUN_EXPECTANCY`)으로 선택지마다 평균 몇 점이 나는지 따져서, 가장 높은 쪽이 최선입니다. 차이가 아주 작으면 함께 좋은 판단으로 인정합니다.

그래서 같은 타구라도 아웃 카운트에 따라 최선이 달라집니다(1사 3루 희생플라이는 뛰고, 무사면 아슬아슬할 때 머무는 식). 실제 결과(세이프·아웃, 잡힘·떨어짐)는 운이 섞이고, 결과 화면에서 판단과 운을 따로 보여 줍니다.
기본 상황 25개(한 베이스 더 9, 플라이 10, 땅볼 6)는 해설을 직접 썼고, 랜덤 연습에는 생성 상황 350개(한 베이스 더 75, 플라이 111, 땅볼 164)가 함께 나옵니다.

## 실행

```bash
npm install
npm run dev      # 개발 서버 (내야 수비 http://localhost:5173, 주루 판단 http://localhost:5173/runner.html)
npm run build    # 타입 검사 후 dist/에 정적 파일로 빌드 (index.html, runner.html)
```

`dist/`는 정적 파일이라 아무 웹 호스팅에나 올리면 됩니다.
`node scripts/build-artifact.mjs <출력 파일> [index.html|runner.html]`을 실행하면 그 페이지만 따로 빌드해서 CSS와 JS를 인라인한 한 장짜리 HTML을 만들어요 (claude.ai 아티팩트 게시용).

## 모드

- **판단 모드**: 키보드로 던질 곳이나 갈 곳을 고릅니다. 판단 순간에 슬로모션이 걸립니다.
- **액션 모드**: `W` `A` `S` `D`로 직접 움직입니다. 공이 지나가는 길로 가면 자동으로 잡히고(못 잡으면 공이 외야로 빠짐), 던질 베이스를 조준하고 좌클릭해서 송구하거나 공을 든 채 직접 아웃을 잡습니다. 포스 상황인 베이스는 밟기만 하면 되고, 포스가 아닌 주자는 다가가서 태그해야 합니다(베이스만 밟아서는 아웃이 안 됨). 포스 주자 옆을 지나가도 자동 태그되지 않고, 베이스를 밟아야 병살로 이어집니다. 위치 판단 상황은 갈 곳까지 직접 뛰어가야 하고, 공(송구)이 그곳에 가는 순간의 위치로 판정합니다. 난이도는 플레이 전체 속도(0.5배, 0.7배, 1배)이고, 기록은 판단 모드와 따로 저장됩니다.

## 소리

타격음, 포구음, 송구 소리, 아웃·세이프 신호음, 결과 효과음을 파일 없이 브라우저에서 합성합니다(`src/sound.ts`). 첫 화면에서 소리를 끄거나 음량을 조절할 수 있고 설정은 저장됩니다.

## 휴대폰

판단 모드는 휴대폰에서도 할 수 있습니다. 화면을 한 손가락으로 끌면 시점이 돌아가고, 베이스(또는 화면의 베이스 표시)를 누르면 그쪽으로 던집니다. 아래 선택지 버튼도 그대로 쓸 수 있어요. 액션 모드는 키보드가 필요해서 PC 전용입니다.

## 조작 (판단 모드)

- 마우스: 시점 이동 (화면을 클릭하면 마우스가 잠기고, Esc로 풉니다)
- 클릭: 바라보는 베이스로 송구
- `A` `S` `D`: 1루, 2루, 3루로 송구 (위치 판단 상황에서는 선택지 순서대로)
- `Space`: 홈으로 송구
- 결과 화면: `R` 다시 하기, `V` 리플레이, `N` 다음 상황, `Esc` 목록

"직접 밟기"를 고르면 밟은 다음 어디로 이어 던질지 한 번 더 고릅니다. 위치 판단에서 2루 커버로 받아 앞 주자를 잡았을 때도 1루로 이어 던지기(병살)를 직접 고릅니다. 액션 모드에서는 밟은 뒤 다시 조준하고 좌클릭해요. 뒤 주자를 먼저 잡으면 앞 주자의 포스가 풀려서 그 베이스는 태그 플레이가 됩니다.
선택지는 타격 순간부터 떠 있고, 공을 잡기 전에 미리 고르면 잡자마자 던집니다(판단 시간 0초). 안 골랐으면 공을 잡는 순간 슬로모션이 걸리지만 주자는 계속 뜁니다. 늦게 고르면 송구도 늦어져서 세이프가 됩니다.
난이도는 슬로모션 배율입니다 (입문 0.1배, 보통 0.35배, 실전 1배).
목록 화면에서 "타구 숨기기"를 켜면 브리핑에 카운트·주자·수비 위치만 나오고, 타구는 공이 맞는 순간 공개됩니다.

## 구조

|---|---|
| `src/config.ts` | 주자 속도, 송구 속도, 구속 범위, 판단 점수 가중치 등 모든 수치 (주루 판단은 `RUNNER`, `RUN_EXPECTANCY`) |
| `src/coords.ts` | 필드 좌표계와 베이스 위치 |
| `src/field.ts` | 구장 모델링 (잔디, 흙, 라인, 펜스, 관중석, 조명탑, 전광판) |
| `src/players.ts` | 마네킹 선수와 자세 |
| `src/scenario.ts` | 상황 타입과 송구 판정 엔진 (포스, 태그, 귀루, 병살, 실점) |
| `src/scenarios.ts` | 기본 상황 36개 데이터와 기본 수비 위치 |
| `src/generated.ts` | 상황 생성기: 포지션별 타구 3종 × 주자 배치 × 아웃 × 안 밀리는 주자의 행동(뛴다/멈춘다), 번트(강한/느린 번트 × 주자 배치 × 아웃) |
| `src/explain.ts` | 생성된 상황의 해설을 판정 결과로부터 규칙으로 작성 |
| `src/timeline.ts` | 한 플레이를 시간의 함수로 만드는 곳 (공, 주자, 수비수 움직임) |
| `src/game.ts` | 게임 흐름, 1인칭 카메라, 리플레이, 입력 |
| `src/ui.ts` | 상황 목록, 브리핑, 결정 패널, 결과 화면 |
| `src/progress.ts` | 상황별 기록과 설정 저장 |
| `src/sound.ts` | 효과음 합성 (Web Audio) |
| `src/runner.ts` | 주루 판단 공통: 세이프 확률, 기대 득점, 판단 단계와 판정, 타임라인 형식 |
| `src/runExtra.ts` | 한 베이스 더 |
| `src/runFly.ts` | 플라이: 타구 판단(스타트·하프웨이·태그업 준비)과 태그업 |
| `src/runGround.ts` | 땅볼 진루: 포스 판단, 내야 수비 엔진으로 수비 플레이 계산, 땅볼 상황 생성 |
| `src/runPlay.ts` | 한 번의 주루 플레이: 단계별 판단을 모아 타임라인과 결과를 만든다 |
| `src/runScenarios.ts` | 주루 기본 상황 25개와 상황 생성기 |
| `src/runExplain.ts` | 생성된 주루 상황의 해설 |
| `src/runMain.ts` | 주루 판단 페이지의 시작점 |
| `src/runMenu.ts` | 주루 판단 첫 화면 (종류별 탭 목록) |
| `src/runGame.ts` | 주루 판단 게임 흐름, 1인칭 주자 카메라, 입력 |
| `src/runUi.ts` | 주루 브리핑과 결과 화면 |

송구 판정은 "공이 베이스에 도착하는 시간"과 "주자가 도착하는 시간"을 비교해서 계산합니다. 상황의 최선은 공을 잡자마자 결정했을 때를 기준으로 고정하고, 판단 속도는 따로 평가합니다(최선이었지만 늦음, 늦은 시점에선 가장 나은 선택 등). 결과가 거의 같은 선택이 여럿이면 모두 "좋은 판단"으로 인정합니다. 커버 들어가는 수비수도 실제로 베이스까지 뛰어가는 시간을 계산해서, 커버가 늦으면 들어오는 타이밍에 맞춰 던집니다. 내가 커버하는 위치 판단 상황도 같아서, 조금 늦게 들어가면 공을 잡은 수비수가 기다렸다 던져 아웃은 되고(평가는 '늦음'), 주자보다 늦으면 세이프입니다.
최선의 플레이가 잡자마자 던져도 주자와 0.2초(`VALUE.closeMargin`) 이내로 아슬아슬하면, 여유 있게 아웃을 잡는 쪽(보통 1루)도 좋은 판단으로 인정합니다. 결과 화면의 "판단 기준"에서 베이스마다 공이 주자보다 몇 초 먼저/늦게 도착하는지 볼 수 있어요.
번트 상황은 번트 세기(강한/느린)와 주자 배치를 바꿔 가며 만들어서, 앞 주자를 잡을 수 있는 번트와 1루밖에 안 되는 번트가 섞여 나옵니다.
화면에서도 포스아웃(받는 선수가 베이스를 밟고 뻗어서 받음)과 태그아웃(몸을 숙여 슬라이딩하는 주자에게 태그)을 구분해서 보여 주고, 판정도 "포스아웃!" "태그아웃!"으로 따로 나옵니다. 태그가 필요한 플레이는 태그 시간만큼 불리하고, 같은 아웃이라면 태그 플레이와 먼 송구는 위험한 선택으로 보고 점수를 깎습니다.
수치는 아직 WBD 영상으로 맞추지 않은 임시값이라 `src/config.ts`에서 조정하면 됩니다. 주루 쪽은 리드를 잡고 뛰는 주자 속도(`RUNNER.speed`), 외야수 송구 속도(`RUNNER.throwSpeed`), 잡고 던지기까지 걸리는 시간(`RUNNER.release`)이 판단을 가장 크게 바꿉니다.

주소 끝에 `?view=tv`를 붙이면 홈 뒤에서 내려다보는 중계 시점으로 볼 수 있습니다 (구장과 움직임 확인용).
